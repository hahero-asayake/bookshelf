## 4.「PCは段を積まない」の実装箇所（コードを grep して確認した分）

計画書は「4か所」と書くが、499-step3-arch.md §3（この前提の実測・列挙をしていたはずの節）は `TESTS_PLACEHOLDER` のまま＝recovered文書で本文が失われている。**「4」という件数そのものは、この文書からは確認できない。** 実際にコードを読んで見つけた、PC/モバイルで履歴の積み方が分岐する箇所は次の3つ：

1. `js/nav-state.js:413-414` — `NavState.open(id, extra, close, meta)`：`if (!mobile) return { op: 'none', skipped: 'pc' };`。汎用の面オープン入口（オーバーレイ管理役からの経由を含む）。
2. `js/bookshelf.js:13283-13285` — `_modalHistPush(id, close, {...})`：`if (!mobile) return;`。旧来の直呼び約30か所と `_overlays()`（13267行目）の両方がここを通る、実質的に唯一の中央ゲート。
3. `js/nav-state.js:277-279` — `reduce3` の `openBook3` 分岐：`if (input.mobile) faces = [...]`。本の詳細（`showBookDetail`）を開く経路はここを通り、PCでは `faces` に追加されない＝履歴が積まれない。呼び出し元は `js/bookshelf.js:3027`（本をクリックして開く）と `js/router.js:154`（ハッシュ直叩き／進む戻るで着地）の2か所。

`mobile` 判定の根は1つ：`js/bookshelf.js:13185-13187` の `_isHistMobile()`（`matchMedia('(max-width: 900px)')`）。

U0a で実際にテストを書く時は、この3箇所（または計画が指す4箇所目が別にあれば、そのときに見つけたものを追記する）それぞれについて、「PC幅でその面を開く → ブラウザの戻るを押す → アプリの外に出る（今の振る舞い）」を固定する。対象の面の候補：本の詳細（B2〜B4 のPC版）、設定モーダル、記事エディタの各面（art-fs 等）、公開パネル系の面。

## 5. 820px の境目の矛盾（確認済み）

- JS の判定は1か所・900px 境目：`js/bookshelf.js:13185-13187` `_isHistMobile()` が `matchMedia('(max-width: 900px)')`。820px では `mobile === true`。
- CSS のメディアクエリは複数の境目に分かれている（`css/bookshelf.css` を grep して確認）：
  - `max-width: 768px`（約9か所：3303・3822・6539・6713・7644・7955・8261・8290 等）
  - `max-width: 900px`（4か所：2957・4639・4961・5082）
  - `max-width: 760px`（4か所：4625=コメント中・5125・5147・7982）
  - `min-width: 769px` / `min-width: 901px`（PC側の対になる境目：3797・7640・8283 / 8054）
- 結果：**820px の端末では、JS は「スマホ」と判定する（履歴を積む）が、`max-width: 768px` のCSSは発火しない（レイアウトはPCのまま）**。履歴の段と見た目が、別々の境目で切り替わる。499-step3-arch.md 39〜40行目の記述と一致。
