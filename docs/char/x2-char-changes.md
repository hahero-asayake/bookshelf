# X2 で期待を書き換えた char テスト（`// CHAR→X2`）

イシュー#521。書き換えたのは `tests/e2e/char/widgets.spec.js` の、`// CHAR:` 印が付いていた W1・W2・W5・W6 の4件だけ。
W3・W4 は CHAR 印が無いため触っていない。W8 の2件（Esc・戻る）は W1〜W6 の範囲外のため触っていない（印は `// CHAR:` のまま）。

| 件 | 元の期待（今の振る舞いの固定） | 書き換えた期待（X2 の後） |
|---|---|---|
| W1 | ツールバーから追加した小は末尾に入り、先頭の小の隣（index 1）には入らない | 先頭の小の「＋この後ろに追加」→候補（2手）で index 1 に入り、先頭の小と同じ行になる |
| W2 | 部品を外した穴は、別の部品をドラッグしても埋まらない（個数だけを確認） | 外した後に「＋ここに追加」の枠が見え、先頭の小を枠へドラッグすると穴の位置（2列：今日の一冊の右、12列：最近の本の右）に入り、同じ行になる |
| W5 | ×で確認なしに外れ、「元に戻す」の toast が出ない | ×で確認なしに外れ（同じ）、「元に戻す」の toast が出て、押すと並びと span が元どおりになる |
| W6 | つまみにフォーカスして↓↓を押しても、並びが変わらない | ↓↓で先頭が3番目に動き、フォーカスはつまみに残り、aria-live で「3 番目に移動しました」と読み上げる |

## テストを書く時に分かったこと（W2）

- ×を押すと、内側のスクロール容器が下へスクロールする（`window.scrollY` は0のまま）。ドラッグの前に `scrollIntoView` で先頭の部品を画面に戻す。
- 既存の `mouseDrag` は、閾値（6px）を超えた最初の移動で落とす先へ飛ぶため、枠の上での pointermove が起きない。閾値を超えてから刻んで動かす。
- 1024 では、細い小のカードの操作欄が2行に折り返すため、カードの中央は大きさの選択欄に当たる（ドラッグが始まらない＝仕様どおり）。カードの下の方（本体）を掴む。
- 外した直後の「元に戻す」toast（6秒）は右下に出る。W2 では消えるのを待ってからドラッグしている（重なりが原因ではなかったが、条件をそろえるため残した）。

新しく足した E2E は `tests/e2e/char/x2-widgets.spec.js`（枠が常に見える・枠で部品の位置が変わらない・W2 の2手・W1 の2手・選んで置く・W6 のキーボードだけ・保存データの形）。
