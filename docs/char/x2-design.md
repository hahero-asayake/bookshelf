# X2 設計メモ：穴の「＋ここに追加」枠・選んで置く・↑↓・元に戻す（イシュー#521 step1）

出典はすべて origin/main 93188cd の実コード。実測は `tests/e2e/char/x2-measure-tmp.spec.js`（使い捨て・commit しない）で、char の6端末について取った（結果は /tmp/x2-measure/*.json と *.png）。

## 1. 保存データの形（変えない）

- 場所：`userData._storage.main.home.widgets`（js/dashboard.js:9, 147-185）。
- 1件の形：`{ id, span, spanMobile?, config? }`。並びの順＝表示の順。
  - `span`：PC の列数（3/6/9/12。古いデータには 4/8 もある＝`spanToSizeKey` で最も近い大きさに読み替える。:88-97。CSS の `span-4`/`span-8` は残っている＝css/bookshelf.css:1928-1933）。
  - `spanMobile`：`'half'|'full'`。無い時は `span>=8 ? full : half`（:104-117）。見出しは常に full。
  - `config`：部品ごとの設定（heading の `text`・recent-books などの `limit`。:603, 657）。
- 読み込みの時の変換：廃止した id（heatmap など）は reading-stats に寄せ、知らない id は捨てる（:152-165）。`uid = id#index` は保存しない派生値（:167）。
- 保存の時（`saveLayout` :173-185）：`id, span` と、ある時だけ `spanMobile`・`config` を書く。
- **X2 で変えるのは並びの順と、新しい要素の追加だけ**。新しいキーは足さない。穴の位置は保存しない（毎回の描画で並びから計算し直す）。
- 見本：`tests/fixtures/x2-saved-layout.json`（古い span 4/8、spanMobile、config、廃止 id の heatmap を含む）。読み込んだ時の期待値＝id の順は `counter-total, counter-shelves, counter-unrated, heading, recent-books, today-pick, pinned-memo, reading-stats(heatmap から), reading-stats`。today-pick は `span-4`、pinned-memo は `span-8 m-half`。

## 2. 格子と穴（実測）

| 端末 | 格子の幅（px） | 列の数 | 流し方 | 既定の並びでできる穴 |
|---|---|---|---|---|
| 390・768・820（タッチ） | 352 / 730 / 782 | 2（`viewport.isNarrow()`＝900px 以下。css/bookshelf.css:7859） | row | 1つ：今日の一冊（半分）の右の1列（全幅の本棚ハイライトが次の行へ送られるため） |
| 1024（タッチ） | 446（左右のペインで狭い） | 12 | row | 2つ：最近の本（9）の右の3列、今日の一冊（6）の右の6列 |
| 1440・1920 | 862 / 1342 | 12 | row | 1024 と同じ2つ |

- `grid-auto-flow` はどの端末でも `row`（詰めない）。実測の座標は、下の模擬計算と一致した。
- 1024 の穴（3列）の幅は約99px、高さは同じ行のカードの高さ（205px）。44px 以上で押せる。
- **390 にも穴はできる**（2列のため。1列ではない）。ただし、並びによっては穴が1つも無い時がある（例：全部の部品が全幅、または半分が偶数個ずつ並ぶ時）。既定の並びでは、小（カウンター）の行は埋まっている＝「小の隣」になる穴は無い。

### 穴の計算（純粋な関数にして、vitest で試す）

```
computeHoles(items:[{cols}], C) -> [{ index, col, row, width }]
  col=0,row=0
  for i,it: w=min(it.cols, C)
    if col+w > C:  hole{index:i, col, row, width:C-col}; row++; col=0   // 入らずに次の行へ送られた分
    col += w; if col==C: row++, col=0
  if col>0: hole{index:items.length, col, row, width:C-col}             // 最後の行の残り
```

- `cols` は、PC では `span`、2列では half=1・full=2（見出しは 2）。
- `index` は「穴に入れた部品を、並びのどこに挿入するか」（＝穴の後ろに送られた部品の前）。これで保存の形は変わらない。
- 枠は DOM 上で、`index` の位置の部品の直前に `.widget-hole` として差し込む。`grid-column: span <width>`（2列の時は `m-` 側のクラス）にして、流し方の結果、元の穴の位置にちょうど収まる（最後の行の残りは末尾に置く）。枠を足しても他のカードの位置は変わらない（穴の幅ぴったりなので）。
- 末尾の「＋ここにウィジェットを追加」カード（:287-297）とツールバーの「ウィジェット追加」（:201）は残す。最後の行の残りの穴と末尾のカードが並ぶ時は、穴の枠を優先し、末尾のカードは次の行に置く（今のまま）。

## 3. 候補を大きさで絞る規則

- 穴の幅 `width`（列数）に入る大きさだけを候補に出す。PC：部品の `allowedSizes` のうち `SIZE_COLS[k] <= width` があるものだけを出し、置く時の大きさは「入る中で最も大きいもの」とする（例：3列の穴→小、6列の穴→中または小）。2列：穴の幅は常に1（＝半分）なので、`allowedSizes` に sm か md がある部品だけを出し、spanMobile を `'half'` で置く。PC 用の span は `defaultSpan` と、入る大きさのうち小さい方にする。
- 候補の一覧（既存の `.widget-picker-panel` :537-580 を使う）に、大きさを選ぶ欄を足す（PC は 小/中/大/全幅、スマホは 半分/全幅。穴から開いた時は入らない大きさを disabled にする）。ツールバーと末尾のカードから開いた時は、すべての大きさを選べ、末尾に入る（今の動き＋大きさの選択）。
- 見出し（xl のみ）は、全幅の穴（＝行の頭からの穴）でない限り候補に出さない。

## 4. 小の隣に小を置く（W1）：穴が無い時

穴の枠だけでは、小の行が埋まっている既定の並び（全端末）で W1 を2手で満たせない。案を2つ比べた。

| 案 | 中身 | 手数 | タッチで押せるか | 全幅で同じか |
|---|---|---|---|---|
| A：行の間に挿入の線（②の例） | カードとカードの間に細い「＋」の線を出す | 2手（線→候補） | 横に並ぶカードの間は gap が 0.7〜1rem しかない＝44px を取れない | 縦の線と横の線が要る |
| **B：カードの「この後ろに追加」（推奨）** | 編集モードのカードの操作欄（×・大きさの隣）に「＋」を足す。押すと、そのカードの直後に入れる候補の一覧が出る | 2手（＋→候補） | 操作欄のボタンと同じ大きさ（X5 で44pxにそろえる対象と同じ） | 全端末で同じ |

- 推奨は B。理由：タッチで押せる大きさが取れる。PC と2列で同じ。保存は「index の位置に挿入」だけで変わらない。挿入すると後ろが1つずつずれる（穴の枠は、ずれない場所に入れる手段として残す）。
- W2（空きに置く）は穴の枠で2手（枠→候補）。

## 5. 選んで置く・↑↓・元に戻す

- つまみ（`.widget-grip` :266）を `<button>` にし、`aria-label="「<名前>」を移動"`。今はフォーカスが当たらない（W6）。
- 状態：`idle` →（つまみを押す・Enter/Space）→ `picking{uid}`：カードに `is-picking`、他のカードと穴の枠に「ここへ」を出し、aria-live で「移動先を選んでください」を読み上げる。
  - `picking` でカードを押す → その前に入れる（`_reorderWidgetByIndex`）。穴の枠を押す → 穴の index に入れる。同じつまみ・Esc・編集モードの終了 → `idle`（何もしない）。
  - Esc は X1 の Surface の Esc より先に capture で受け、picking の時だけ止める（reorder.js のドラッグ中の Esc と同じ型）。
- ↑↓：つまみにフォーカスがある時、1つ前／後ろへ移し、描画し直した後もフォーカスをつまみに戻し、aria-live で「n 番目に移動しました」を読み上げる。記事エディタのブロックは **Alt+↑↓**（js/bookshelf.js:9900-9904・`focusGrip/announce`）なので、Alt 付きも同じに受ける（同じ操作は同じ挙動）。
- ドラッグ：`_bindPointerReorder` の opts に `holeSelector: '.widget-hole'` と `onDropHole: (uid, holeEl) => 穴の index に移す` を足す（reorder.js:31-35, 119-172。穴は、指の下にカードが無い時だけ拾われる）。
- 元に戻す（W5）：`_removeWidget` で外す前の `{entry, index}` を持ち、`UndoToast.show('「<名前>」を外しました。', { onUndo })`（js/ui/undo-toast.js）で、元の index に `id/span/spanMobile/config` をそのまま戻す。1段だけ持つ（記事の `_artBlockUndo` と同じ型）。
