# #612 の ADR の下書き（08_意思決定記録へ入れる前・番号は入れる時に取る）

M（項目ごとの合わせ）は後半で足す。件数は、書く物がある保存では「変えたファイルの数＋1（版の印）」になる。

### ADR-xxx ハブの一括保存は変えたファイルだけ送り、書いた後の ETag を覚えて照合する (2026-11-14・イシュー#612・②承認)

- **背景**: ハブへの一括保存 (POST /data/batch) は、毎回「固定7本＋本棚の数」を全部送っていた (本棚20個で27件)。#600 (ADR-157) でハブ側を並列にしたが、送る件数そのものは減っていなかった。調べる中で、件数より重い穴が見つかった。
  - **直す前は、2台目の2回目以降の保存で、相手の変更を黙って上書きしていた。** 一括保存が成功するたびに、覚えていた ETag を全部捨て、次の保存の前に HEAD で「今の」ETag を取り直して ifMatch にしていたため、照合が必ず通った。変えていないファイルも古い中身で書き直すので、相手が間に書いた短文メモなどが消えた (`scripts/verify/612-step1.md` §0 で再現)。
  - 起動時の標準プラグインの種まき (15件の一括書き込み) でも ETag を全部捨てていたので、種まきをした端末では、読んだ直後の最初の保存の照合も効いていなかった。
  - 存在の確認 (`fileExists`) も、覚えている ETag を「今の」ETag で置き換えていた (保存のたびに bookshelves/all.json で呼ばれる)。
  - library.json は、保存のたびに日時 (`exportDate`) が入るので毎回中身が変わっていた。追加日・取得日の無い本にも、保存のたびに今の時刻が入っていた。
- **決定** (案3改):
  1. 変えたファイルだけ送る。中身が、自分が最後に読んだ・書いた中身と同じ put は送らない。送る物が無ければハブに何も送らない。
  2. ハブは、条件付きの一括書き込みの成功応答で、put した分の ETag を返す (`{etags:{パス:ETag}}`)。アプリはそれを覚えて次の保存の ifMatch に使う。送らなかったファイルの ETag も捨てない。古いハブ (応答に ETag が無い) では、今までどおり全部捨てる。#600 の並列化・打ち切り・使用量の処理は変えない。
  3. 存在の確認は、覚えている ETag を置き換えない。
  4. 追加日・取得日の無い本は、補った時刻を手元の本にも入れる (次の保存から変わらない)。
  5. library.json の日時 (`exportDate`) は、本の一覧が読んだ時・前回の保存と同じなら据え置く。
  6. 保存先の版の印を、小さい専用のファイル `private/sync-stamp.json` (`{ stamp: '<時刻>-<乱数>' }`) に持つ (ADR-162 への追補)。
     - ADR-162 は `exportDate` を「保存のたびに変わる値」として、保存先がこの端末と最後に揃えた後に変わったかを見ていた。5 でこの前提が崩れる (相手が短文メモだけを変えた保存では日時が変わらず、手元を丸ごと採って相手の変更を上書きしうる)。日時を毎回進める形に戻すと、一番大きい library.json を保存のたびに送ることになる。
     - 書く側: 蔵書のまとめ保存 (`BookshelfStorage.syncBatch` の `stamp`) が、書く物がある保存のたびに、同じ書き込みで印を書く。保存先の種類を問わず同じ所で足し、照合は付けない (印なので、後から書いた方が勝ち)。ハブは他に送る物が無ければ印も書かない。GitHub は同じ commit に入れ、古い版の照合 (ADR-159 決定5) にはかけない。
     - 読む側: 控え (`virtualBookshelf_syncBase`) は `exportDate` と印の2つを持ち、どちらかが違えば「保存先は変わった」と見る。「これから書く版」も2つで控える。`exportDate` も見続けるのは、印を書かない古い版のアプリの保存に気づくため。
- **却下した案**:
  - 案1 (変えていないファイルは、本文なしの照合専用エントリで送る): 別のファイルを相手が変えただけで保存が止まる。2台を交互に使うと3択が今より増える。止めずに取り込む形にすると、全種類のファイルで取り込みの処理が要る。
  - 案2 (整合が要る組だけ常に送る): 組の中の変えていないファイルを古い中身で上書きする穴が残る。
  - ハブを触らず、書く前に GET して覚えている中身と比べる: 変えるファイルごとに本文を1回余分に取る。ETag を返す方が軽い。
- **分かっている残り**:
  - 自分が変えていないファイルを相手が変えても、読み直すまで手元は古いまま (上書きはしない)。ファイルをまたぐ食い違いが起きうる。確かめた範囲では、本の無い短文メモ・一覧に無い本が載った本棚ファイルは、読んでも落ちず、保存しても残る。
  - 一覧 (library.json) に無い本の番号が bookshelves/all.json に載っていると、次の保存で all.json から外れる。**直さない。** 利用者が書いた中身は消えない。本を足す・消す時は library.json と all.json を同じ1回の一括書き込みで送るので、普通の操作では起きない。
  - 保存のたびに、all.json の存在の確認で HEAD が1回出る (`detectFormat`)。何も変えない保存でも、ハブへの要求は1回残る (R2 への書き込みは0回)。このイシューでは消さない。
  - GitHub のまとめ保存は対象外 (ADR-159 で照合は入っている)。
- **確かめ方**: `tests/unit/hub-two-devices.test.js` (9件。保存の層から本物のハブ処理までを通す。直す前の版では9件とも赤)。件数は `scripts/verify/612-step2.md` §1 (短文メモ1つの保存で、本棚0個は 7件→1件、本棚20個は 27件→1件)。
