### 分かったこと（step1 の範囲。原因の裏づけは step2）

1. **E は今の main でも起きる**：1/8（#622 は 0/8）。操作の直後（再読込の前）の端末の控えは、8回とも「すべて」本棚の books が3冊、bookOrder.all が4冊で食い違っていた。手動追加の保存（saveUserData の localStorage への書き込み）が、「すべて」本棚を古いまま書いている。これは計画の見立て3と合う。
2. 再読込の後に古い3冊が残るかどうかは、読込時の3択（#622 の R1）にも左右される。
   - 3択が出た回（E 6回・G 7回）は全部3のまま。読込が止まり、古い控えがそのまま出ている。
   - 3択が出なかった回でも、E 1回・G 1回は、フォルダの all.json が4冊になって印も消えた後で、控えは 3/4、表示は3のままだった。#622 の E#1 と同じ形。
   - つまり R1 が直っても、R2 は残る見込み。
3. **同じ型は手動追加だけではない**。
   - 2回目の取込（G）と除外（H）でも、再読込の前の控えが8回とも食い違っていた。
   - G は、1回目の書き出しの後に新しい本を取り込むと起きる。#622 の A・B は、つないだ直後の読込で2つが同じ配列のまま取り込んだので起きなかった、という見立てと合う。
   - 削除（J）は、再読込の前から揃っていた（2/2）。8回とも表示が合った。
