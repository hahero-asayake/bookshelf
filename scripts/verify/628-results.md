# イシュー#628 門のE2E J3-4（390幅）が CI の webkit で1回赤になった件の切り分け

2026-11-14。対象：`tests/e2e/gate/j3-4-back-forward-esc-phone.spec.js`（@gate J3-4・iPhone 相当の 390幅）。

## 結論

- 15b0f9e の CI の webkit で J3-4 phone が1回赤になった**原因は特定できなかった（未特定）**。
- **#616 の変更が原因ではない。** #616 の前（4a1cfad）・直後（15b0f9e）・最新の main で、ローカルの結果に差が無い。#616 の差分は、一覧の本を押す → 詳細を開く経路・引き出し・URL の処理に触れていない。
- テストの書き方に、直すべき所が1つあった。本棚を選んですぐ本をタップしていたため、**本を押す操作が、引き出しの閉じる動き（0.25秒）とぶつかっていた。** 本棚を選んだ後に、引き出しが画面の外へ出たのを確かめてから本を押す形に直した。
- この直しで CI の赤が消えたとは言い切れない。言えるのは「本を押す操作が引き出しとぶつからなくなった」まで。

## 直したこと

1. `tests/e2e/gate/j3-4-back-forward-esc-phone.spec.js`：「操作：本棚 → すべての本 → 本」の3連続のタップを、J3-1 と同じ「操作 → 確認 → 操作」に分けた。
   - 確認：URL が `#/bookshelf/all`・冊数が 5・**引き出しが画面の外へ出た**（`expect(page.locator('#app-sidebar')).not.toBeInViewport({ ratio: 0.01 })`）。
   - URL と冊数は「すべての本」を押して 37〜50ms 後にもう変わる。その時、引き出しの右端はまだ 225〜320px にあり、押す点（x=101）を覆っている。だから URL と冊数だけでは待てない。
   - 引き出しは閉じた後も右の境界線が 0.1px 画面に残る（画面に入っている割合 0.0004）。ratio を付けないと通らない。
2. `tests/e2e/gate/README.md`：webkit で流す時の注意に、上の待ち方を1行足した。

固定の時間待ち・retries・`waitForFunction(async)`・待ち時間の延長は使っていない。アプリのコード（js/）と ci.yml は変えていない。

計り方に使った使い捨ての spec（中の動きの記録・条件の強制・直す前後の比較）は、アプリの内部に触るので tests/e2e には入れていない（作業場所の `_trash/628-probe/` に退避）。

## 直さなかったこと

- `tests/e2e/gate/j8-offline.spec.js` の `tapToBookDetail`（19〜23行）も同じ形（引き出しで本棚を選んですぐ本を押す・閉じるのを待たない）。chromium だけで流れる。#617 が J8 を触っているので、このイシューでは触っていない。
- `j3-4-back-forward-esc-pc.spec.js`・`j4-memo.spec.js` も本棚を選んですぐ本を押すが、1280幅で引き出しが無い。効果の根拠が無いので触っていない。
- E2E は表紙の画像を本物の Amazon のサーバへ取りに行っている（fixture の productImage が空で、アプリが `images-na.ssl-images-amazon.com/images/P/<ASIN>.01.L.jpg` を組み立てる・`js/book-manager.js` の `getProductImageUrl`）。今回の強制では画像が遅れても失敗してもタップは通ったので、J3-4 の赤の原因とは言えない。
- Playwright（1.60.0）はタップの時に click を見張らない（見張るのは pointerdown・pointerup・touchstart・touchend・touchcancel）。webkit では「タップは成功・画面は変わらない」が起こりうる形になっている。今回これが起きた証拠は取れていない。次に同じ赤が出たら、赤の回の画面（詳細が開いていたか・引き出しが開いていたか）を先に見る。
